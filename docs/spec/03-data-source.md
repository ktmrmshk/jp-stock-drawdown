# SPEC 03: データソース（yfinance連携）

- ステータス: Approved
- 対象バージョン: v1.0.0

## 1. 方針

- 株価履歴の取得は [yfinance](https://github.com/ranaroussi/yfinance) のみを使用する。
- ネットワーク取得は `fetcher.py` に集約し、それ以外のモジュールからはyfinanceを直接呼ばない。
- 指標計算（`metrics.py`）はネットワークに依存しない純関数とし、テストではローカルデータを使用する。

## 2. シンボル正規化

入力されたtickerをYahoo Financeのシンボルに正規化する。

| 入力例 | 正規化後 | 備考 |
|--------|---------|------|
| `7203` | `7203.T` | 4桁数字 → 東証（`.T`） |
| `7203.T` | `7203.T` | そのまま |
| `9984.OS` | `9984.OS` | 明示サフィックスはそのまま |

- 日本市場のデフォルトは東京証券取引所の `.T`。
- 許可サフィックス: `T`（東証）, `N`（名証）, `F`（福証）, `S`（札証）, `OS`（大阪=旧）※ 単に受け付けるだけであり、`.T` 以外の動作保証はしない。

## 3. 履歴取得仕様

### 3.1 API呼び出し

```python
import yfinance as yf

ticker = yf.Ticker(symbol)
df = ticker.history(
    period=period,        # 例: "max", "1y"
    start=start,          # 指定時のみ（yyyy-mm-dd）
    end=end,              # 指定時のみ
    auto_adjust=False,    # 生のCloseを取得（JP銘柄の調整値問題への対処）
)
```

### 3.2 前提・制約

- 使用カラム: `Close`（終値）を指標計算の基準とする。`High` / `Low` / `Date` は出力の補助情報に使用。
- **Adj Closeは信頼しない**。日本株の配当・分割調整はyfinanceで不整合が発生しうるため、指標計算には未調整の `Close` を使う。
- 返却DataFrameのインデックスは日付（DatetimeIndex）。日付は **Asia/Tokyo** タイムゾーンを前提とし、出力では日付（`yyyy-mm-dd`）で表現する。
- 通貨はJPY。為替変換はしない（そのまま出力）。

### 3.3 取得パラメータ

- `--period max` がデフォルト（全期間）
- `--start`/`--end` 指定時は period より優先して渡す

### 3.4 社名（best-effort）

- 社名は `ticker.info`（または `ticker.get_info()`）から取得を試みる。
- 取得失敗・`--no-name` 指定時は `name` を `null` とする。**社名取得失敗でコマンドを失敗させない**。
- 社名取得は時間がかかるため、`--no-name` でスキップ可能とする。

## 4. エラー処理（取得系）

| 状況 | 処理 |
|------|------|
| ネットワーク断・タイムアウト | `DataFetchError` として報告（exit 3） |
| レート制限（`yfinance` の `YFRateLimitError`） | メッセージに「レート制限」と明記（exit 3） |
| データが空（DataFrameが空） | `NoDataError` として報告（exit 4） |
| 不正シンボル | フェッチ前に引数検証で排除（exit 2） |
| デリスティング済み等で履歴なし | `NoDataError` |

- 1銘柄の失敗が他の銘柄の処理を止めないこと（部分失敗の扱いは [06-error-handling.md](./06-error-handling.md) 参照）。

## 5. レート制限への配慮

- 複数銘柄は **順次取得**（並列はしない）し、銘柄間は必要最小限の待機を入れる。
- 再試行（retry）は1回までとし、それでも失敗したらエラー報告する。
- 実装上、`--verbose` 時に取得の診断ログ（取得シンボル・行数・所要時間）をstderrに出す。

## 6. テスト戦略

- ネットワークを必要とするテストは原則書かない（CIで安定しないため）。
- `fetcher.py` の関数は**インターフェースを注入可能**にし、テストでは `tests/fixtures/sample_history.csv` を返すモックを使う。
- ゴールデンデータは少なくとも以下の条件を満たすこと:
  - 10行以上のOHLCデータ
  - 単調増加後の下落（ドローダウンが発生するデータ）
  - 少なくとも1つの欠損値（NaN）を含む日があると望ましい
